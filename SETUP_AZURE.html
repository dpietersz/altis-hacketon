Altis hackathon — infrastructure

Azure setup & dependencies

Everything we provisioned to get the data pipeline running. Use this to rebuild the backend in a clean subscription.

Everything lives in one resource group rg-altis-hackathon in West Europe.

Step 1Create the storage account & containers

Azure Portal → Create resource → Storage account.

  • Performance: Standard
  • Redundancy: LRS (cheapest, fine for a hackathon)
  • Account kind: StorageV2
  • Hierarchical namespace: disabled (we use plain blob)
  • Networking: Allow access from all networks

Once created, open Data storage → Containers and create three containers: raw, silver, gold.

Grab the access key

Storage account → Security + networking → Access keys → Show next to key1, then copy. You'll paste it into a Databricks secret a few steps below.

Upload the source data

In raw/ create a folder called received_original_data/ and upload the Excel exports from the four portcos. For Tier 2 also create weather_data/ and upload the three KNMI .txt files.

Data retention. Per the challenge brief, all Altis-provided data must be deleted within 3 days after the event from every storage location (including this account).

Step 2Configure Databricks (CLI + auth)

On your laptop:

curl -fsSL https://raw.githubusercontent.com/databricks/setup-cli/main/install.sh \
    | sh -s -- -b ~/.local/bin
databricks --version

Then in the workspace UI: top-right avatar → Settings → Developer → Access tokens → Generate new token (no expiry is fine for a hackathon). Copy the PAT.

Write ~/.databrickscfg with mode 0600:

[DEFAULT]
host  = https://adb-<workspace-id>.<region>.azuredatabricks.net
token = dapi<your-token>

Verify:

databricks current-user me

Step 3Create the Databricks secret scope

Storage and SQL credentials live in a server-side secret scope called altis. The notebooks read them via dbutils.secrets.get(). Two secrets:

databricks secrets create-scope altis
databricks secrets put-secret altis storage_key  --string-value '<key1 from storage account>'
databricks secrets put-secret altis sql_password --string-value '<SQL admin password>'
databricks secrets list-secrets altis
Why a secret scope? GitHub's push protection blocks raw storage keys committed to source. Keeping them in Databricks means the notebooks stay safe to commit.

Step 4Create the SQL Server and database

Azure Portal → Create resource → SQL Database.

  • Server: create new → name atlis
  • Server admin login: sasqladmin; remember the password
  • Compute: Serverless, General Purpose, 1 vCore
  • Database name: altis
  • Backup redundancy: LRS

Open the firewall for Databricks

SQL Server atlis → Security → Networking → Public access:

  • Public network access: Selected networks (or All networks for the hackathon)
  • Exceptions: ✓ Allow Azure services and resources to access this server
  • If the Lovable host calls from outside Azure and gets a login error, switch to All networks

Step 5Run the pipeline

Import each notebook into the workspace then submit a serverless run. The notebooks live in backend/databricks/notebooks/.

databricks workspace mkdirs /Users/<your-email>/altis
for nb in 03_silver_cleanse 05_gold_classify 06_gold_forecast \
          07_gold_covenant 11_silver_gold_weather 08_export_to_azure_sql; do
  databricks workspace import /Users/<your-email>/altis/$nb \
    --file backend/databricks/notebooks/${nb}.py \
    --language PYTHON --format SOURCE --overwrite
done

Then submit each run via the workspace UI or via databricks jobs submit --json @<runspec>.json. Sample run specs are in backend/databricks/notebooks/.

Order of execution for a clean rebuild:

  1. 02 / 04 — discovery (no writes; optional once you trust the data)
  2. 03 — silver cleanse (writes silver/bookings.parquet)
  3. 05 — gold classify (writes gold/bookings_classified.parquet + portfolio KPI)
  4. 06 — 13-week forecast (writes the forecast + assumptions)
  5. 07 — covenant headroom + consolidated
  6. 10 + 11 — Tier 2 weather (workable days, climate normals, weather-adjusted forecast)
  7. 08 — push every gold table to Azure SQL
  8. 09 / 12 — chart notebooks (Tier 1 and Tier 2; for reviewing only)

Cost & cleanup

Everything is serverless or pay-as-you-go:

  • Storage account: ~€0.02 / GB / month (a few cents for our data)
  • SQL serverless: pauses after 12 hours idle (set during DB creation); ~€0.50 per active hour
  • Databricks serverless: charged per DBU; one full pipeline run <€2

Tear it all down after the event

Delete the resource group:

az group delete --name rg-altis-hackathon --yes --no-wait

Then rotate any keys/PATs you exposed and run git filter-repo against this repo to remove any committed data.
