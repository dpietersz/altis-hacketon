Altis hackathon — frontend

Build the Lovable frontend

How to clone, install and run the dashboard locally. Then how to point it at the Azure SQL backend.

What this frontend is

The dashboard is built in Lovable, a visual AI builder that generates a standard Vite + React + TypeScript + Tailwind + shadcn/ui project under the hood. Editor: https://lovable.dev/projects/e0af25e0-3233-4d46-939c-587389f1498d.

Once exported, the project is a normal Node/Vite app — no Lovable runtime needed. The judges can clone & run it like any web project.

Step 1Get the source code into this repo

Lovable lets you push the project to GitHub or download as a ZIP. Either way, the code should land in frontend/ at the root of this repo.

Option A — Lovable → GitHub (recommended)

  1. Open the Lovable project
  2. Top-right menu → Connect to GitHub (one-time auth)
  3. Push to GitHub → pick a new repo (e.g. altis-frontend)
  4. Add it to this repo as a subtree or copy the files into frontend/

Option B — Direct download

  1. Lovable project → ... menu → Download as ZIP
  2. Unzip into frontend/ at the repo root

Step 2Install dependencies and run locally

Lovable projects use the standard JS toolchain. We recommend Bun, but npm or pnpm also work.

cd frontend
bun install              # or npm install / pnpm install
bun run dev              # or npm run dev / pnpm dev

The dev server typically starts on http://localhost:5173.

Build for production

bun run build
bun run preview          # serves the prod build locally to verify

Step 3Connect it to the Azure SQL backend

Azure SQL doesn't accept connections straight from a browser (CORS + no native TLS proxy). The Lovable app needs a thin server proxy. There are two clean patterns:

Pattern A — Lovable's built-in backend (Supabase)

Lovable can wire a Supabase project to your frontend automatically. We can then write Supabase edge functions that query Azure SQL using mssql/tedious and serve JSON to the frontend. Connection details from HANDOFF_LOVABLE.md go in the edge function as Supabase secrets.

Pattern B — Tiny Node API in this repo

If we don't use Supabase, ship a minimal Node/Express or Hono server alongside the frontend that proxies SQL queries and returns JSON. Quick scaffold:

mkdir -p api && cd api
bun init -y
bun add hono mssql
# server.ts — see HANDOFF_LOVABLE.md for the SQL queries
Credentials. Do NOT put the SQL password in the frontend code — it would ship to the browser. Always read it server-side from an environment variable. The dev-time values are listed in HANDOFF_LOVABLE.md.

Step 5Deploy (optional)

For the demo, running locally with bun run dev is enough. To put it on the public web:

  • Lovable Publish — easiest. Click Publish in the Lovable UI; it deploys to <slug>.lovable.app.
  • Vercel / Netlify — connect the frontend GitHub repo, set the SQL env vars in the dashboard.
  • Azure Static Web Apps — natural fit if everything else stays in Azure; their managed functions can do the SQL proxy.

If the judges want to run it from scratch

  1. Clone this repo
  2. Read SETUP_AZURE.html if they want to provision their own backend, OR connect to ours using credentials from HANDOFF_LOVABLE.md (valid only during the event)
  3. cd frontend && bun install && bun run dev
  4. Open http://localhost:5173
Data retention. The Azure backend (and any data it returns) must be destroyed within 3 days after the event per the challenge brief.
